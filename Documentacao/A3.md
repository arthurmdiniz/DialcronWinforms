# Orientações - Trabalho A3: Prático

**Disciplina:** Garantia da Qualidade de Software / Gestão e Qualidade de Software (GQS)
**Professor:** Daniel Henrique Matos de Paiva
**Instituição:** Ânima Educação

## 📌 Regras Gerais

* **Equipe:** Mínimo de 03 e máximo de 05 alunos.

* **Linguagem de Programação:** C# (csharp), Java ou Python.

* **Objetivo:** Desenvolver ou refatorar uma solução de software para um problema do mundo real, contemplando todas as boas práticas de GQS.

* **Impacto:** O projeto deve estar associado a alguma ODS (Objetivos de Desenvolvimento Sustentável).

## 📦 Entregas a serem realizadas

1. **Documento de Especificação (Formato .pdf)**

   * Informações dos integrantes do grupo (NOME e RA).

   * Problema a ser resolvido.

   * Solução final que será entregue.

   * Quais tecnologias foram utilizadas.

   * Quais os desafios enfrentados durante o desenvolvimento.

   * Quais os aprendizados obtidos pela equipe.

2. **Código Fonte e Repositório**

   * Entregar o link do repositório (GitHub e/ou similar).

   * O repositório deve ser criado no período (ano e semestre) atual da disciplina.

3. **Apresentação**

   * PowerPoint (.pptx / .pdf) para a apresentação final do projeto.

   * A apresentação presencial/síncrona deverá ter de 10 a 15 minutos.

4. **Vídeo Pitch**

   * Duração de até 05 minutos.

   * Publicado no YouTube ou Google Drive (garantir que o link esteja público/acessível).

5. **Relatório Final**

   * Preenchimento do relatório no Way Hub.

## ✅ Checklist de Avaliação e Requisitos Técnicos

A pontuação será distribuída com base nos seguintes critérios obrigatórios:

* \[ \] **Funcionamento:** A aplicação deve "rodar/funcionar" no dia da apresentação.

* \[ \] **Linguagem:** Escrita em C#, Java ou Python.

* \[ \] **Versionamento de Software (Git):**

  * \[ \] Uso do GitFlow (Mínimo de 03 branches).

  * \[ \] Uso de Git Semântico (Commits semânticos e descritivos).

* \[ \] **Qualidade de Código:**

  * \[ \] Código Limpo (Clean Code).

  * \[ \] Todos os algoritmos devidamente indentados.

  * \[ \] Tratamento de erros na aplicação (Try/Catch e afins).

  * \[ \] Realização de refatorações no código.

* \[ \] **Testes:**

  * \[ \] Possuir modelo de Testes Unitários (TDD) em alguma parte do código.

* \[ \] **DevOps / Automação:**

  * \[ \] Continuous Integration (CI) e/ou Continuous Delivery (CD) (se possível, implementar CI/CD).

* \[ \] **Escopo:** O problema proposto foi efetivamente resolvido pela solução.

### 🌟 Diferenciais (Para um excelente portfólio)

* \[ \] Integração com algum serviço externo (API).

* \[ \] Integração com algum banco de dados.

## 💡 Ideias de Aplicações

* Aplicação Console ou API's diversas.

* Aplicação no modelo Windows Forms.

* Aplicativos variados: Gerenciamento de Tarefas, Calendário, App de anotações, Gestão Escolar, Jogos, Gestão Hospitalar, etc.
